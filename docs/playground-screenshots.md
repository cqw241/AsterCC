# AsterCC 课程展示截图指南

报告 4.4 已放入四张实际运行截图，可以直接使用。若希望亲自重拍，建议保留 **4 张核心图**，另选 **1—2 张补充图**。截图需要同时表达输入、变换或结果，优先保证代码和数值可读。

## 启动与取景准备

1. 在终端进入独立 worktree：

   ```bash
   cd '/mnt/d/学习资料/专业课/大三上/编译技术/实验三-playground'
   bash playground/serve.sh
   ```

2. 打开 `http://127.0.0.1:8000`。如果已能访问，直接使用当前服务即可；端口已占用时无需重复启动。
3. 浏览器最大化，推荐 1440×900 或更大。先用 `Ctrl+0` 恢复 100% 缩放；内容不足以同屏时再用 `Ctrl+-` 调整到 90% 或 80%，以能看清文字为准。
4. Windows 按 `Win+Shift+S` 选择矩形区域，保存 PNG；Linux 可用系统截图工具。报告中不必包含浏览器地址栏、书签和桌面。
5. 可拖动源码／结果分隔条，以及底部终端分隔条。先等加载和编译完成，再截图。

以下操作均使用项目自带示例，不需要自行输入复杂程序。

## 图 1：真实编译运行闭环（必选）

**放置位置：报告 4.4「Playground 展示与新增验证」图 1。**

1. 进入顶部「工作台」。
2. 左上角示例选择「优化综合示例」，选择 **O2**。保持关联图标开启，使 LLVM 同样为 O2；运行参数为 `[]`。
3. 点击「运行」，等待编译和执行完成。
4. 右侧切到 **SSA** 标签；底部切到「终端」。若之前清空过终端，再运行一次。
5. 向下拖动编辑器与终端之间的分隔条，使终端占约四分之一屏幕；保证终端能看到 **1290** 和 **exit 0**。
6. 截下工具栏、左侧源码、右侧 SSA、底部执行结果。源码较长时无需强求全部可见。

**必须看见：** O2、源程序、SSA、1290、exit 0。

**建议图注：**「Stage 3 编译并执行 Aster 优化示例，终端输出 1290，右侧为自定义 SSA。」

## 图 2：LICM 前后 IR Diff（必选）

**放置位置：报告 4.4 图 2；也可用于讲解 4.2 的 LICM。**

1. 完成图 1 的编译后，进入顶部「优化探索」。
2. 数据集选择「当前编译 · main.aster」。若刚重启服务而没有当前任务，可选择 **「优化实验 · kernel」**，它读取已有真实追踪。
3. 函数选择 **main::kernel**。
4. 左侧选择 **06 licm**。上方比较起点应为 **5: gvn**，终点为 **6: licm**。
5. 保持 **IR Diff**，选择并排模式。必要时滚动 Diff，观察乘法 `%14:i64 = mul %1, %2` 的位置变化。
6. 截图应保留 Pass 名称、**8 → 8** 的指令统计，以及底部 **%14 移动 b5 → b0** 的记录。不要仅截两段代码而裁掉变化说明。

**必须看见：** LICM、8 → 8、%14、b5 → b0。

**讲解重点：** LICM 改变动态执行次数，总指令数可以不变。若 Diff 中移动位置不能同屏，保留移动摘要，并用下一张 CFG 图补充说明。

**建议图注：**「LICM 将循环不变量 %14 从 b5 外提至 b0，静态指令数保持 8。」

## 图 3：CFG 与 SSA 定义使用关系（必选）

**放置位置：报告 4.4 图 3。**

1. 保持图 2 的数据集、main::kernel 和 06 licm。
2. 切换 **CFG / SSA**。
3. 图左下角有放大、缩小和适配视图按钮。先适配全部图，再适当放大；拖动空白画布平移，拖动基本块标题可调整节点位置。
4. 在 **b0** 中找到并点击 `%14:i64 = mul %1, %2`。
5. 确认底部值关系显示输入 **%1、%2**，使用者 **%19、%20**；右侧 SSA 会定位到相应指令。
6. 截下 b0、循环头 b4、循环体 b5、回边、右侧 SSA 和底部值关系。小字体时宁可略微放大图，少截无关空白。

**必须看见：** %14 位于 b0；b4/b5 的循环结构；输入及使用者。

**建议图注：**「外提后的乘法位于前置块 b0，循环体通过同一 SSA 值复用结果；CFG 与值使用关系联动显示。」

## 图 4：自举固定点与哈希一致性（必选）

**放置位置：报告 4.4 图 4，可与前面的自举结果表呼应。**

1. 进入顶部「自举仪表盘」。
2. 在「自举固定点」区域选择 **O2**，点击「刷新并校验」，等待完成。
3. 确认 Stage 0 → 1 → 2 → 3、当前制品状态，以及 **当前 Stage 2 / 3 的 LLVM + ELF 逐字节一致**。
4. 展开 **「完整 SHA-256 与制品核对」**。滚动使 Stage 2 和 Stage 3 的 **ELF、LLVM 两类完整哈希** 同时可见，再截取该区域。完整哈希比卡片中 16 位摘要更有证明力。
5. 若同时放不下阶段流程和完整哈希，可以只截哈希与一致性结果，阶段流程由报告已有图和表补充；或者将一张图排成上下两个子图。

**必须看见：** O2、Stage 2/3、两类完整哈希及一致性状态。O0 的同类检查已经有文字和原始记录，不必再截一张重复图。

**建议图注：**「重新计算当前 O2 Stage 2/3 的 LLVM IR 与 ELF 摘要，两类制品分别一致，并与保存的自举记录吻合。」

当前报告采用的现有图 4 是自举流程与性能概览。若改用上述完整哈希取景，也应把图注改为本段建议文字。

## 可选 A：SCCP 常量分支消除

适合希望额外突出优化原理的报告，放在 4.4 图 2 前或 4.2 SCCP 小节。

1. 回到「优化探索」，选优化综合示例的 main::kernel。
2. 左侧选择 **02 sccp**，比较 **1: simplify → 2: sccp**，打开 IR Diff。
3. 滚动到开头的常量条件：优化前可看到 `branch %6, b1, b2`，之后变为 `jump b1`，不可执行的 b2 分支从快照中消失。
4. 保留 **11 → 10** 的统计和前后代码，一张截图即可。

建议图注：「SCCP 根据常量条件保留可执行分支，分支终结指令变为单向跳转。」

如果更想展示 GVN，可改选 **05 gvn**，比较 **4: dce → 5: gvn**：重复乘法 `%15` 被消除，使用被替换为 `%14`，指令数 **9 → 8**。二者选一即可，避免多张近似截图。

## 可选 B：中文／emoji 之后的错误定位

适合放在 4.3 错误处理。

1. 回到「工作台」，选中左侧编辑器内容，用以下短程序替换：

   ```aster
   fn main() -> i64 {
       println("你好🌟"); return missing;
   }
   ```

2. 点击「编译」，等待出现「编译失败」。
3. 底部切到「诊断」，点击 `undefined variable missing` 这一项，编辑器应定位到 `missing` 并显示错误标记。
4. 截下源程序、错误标记和诊断行。中文与 emoji 位于错误之前，能够说明字节列到编辑器列的转换。
5. 拍完后重新选择「优化综合示例」，点击「运行」，恢复正常展示状态。

建议图注：「编译器诊断转换为编辑器位置，中文及 emoji 前缀不使 undefined variable 的定位发生偏移。」
